# 云策2027 · 户外媒介提案工作台

默认客户为食品饮料行业的星巴克，活动“下一站，附近的一杯”为参赛策划设想，非品牌委托。默认档期2027-03-01至03-31，预算200万元。

## 运行

下载本仓库后直接打开 index.html（独立工作台）或 starbucks-proposal.html（客户提案），无需安装即可调预算、增减媒介、核对来源、保存项目和导出独立HTML。

本地服务器：Node.js 18+，在本目录执行 npm start，打开 http://127.0.0.1:8766 。模型设置里输入比赛专户密钥，然后主动调用Flash；密钥不持久化、不进入导出。未配置密钥时使用规则摘要。

## 数据与测算

已读取完整赛题和资料包；通过比赛大数据平台对6个官方门店地标查询500米范围自有媒体，并精确关联红豆2027年3月公交导出。54条覆盖公交候选中51条匹配，43条有可售车辆；旅游1/2/10线未强行替换。公交列表总数552与实际导出431行存在口径差异，成案仅使用实际导出范围。

100万：14辆、5条线路，已知费用65–100万元；200万：28辆、7条线路，128–198万元；500万：71辆、14条线路，321.5–499万元。各档均命中6个门店地标；同一辆经过多个锚点时不重复采购。

刊例月价与每辆制作费按区间计算，上界约束只涵盖已知费用。税费、折扣、计费月定义及其他收费须企业确认。库存为查询时点快照，非锁档；500米指平台轨迹覆盖，非店门步行距离或独立触达。地铁14个站点级候选缺具体出口/面积匹配，未纳入采购组合。未把2023人流外推为2027曝光。

## 在线重查

实时模式另需Python 3（仅标准库）与playwright：npm install --registry=https://registry.npmjs.org 。执行 node competition-browser.cjs，在独立浏览器使用赛题专户登录红豆；然后在本地工作台点击“同步当前档期可售库存”。此功能只按新日期重新查询并导出公交库存，复用已记录的门店覆盖；不修改业务记录，不代表重新核验门店。当前环境的最终同步连接未完成复验，需现场预先联调；失败时保留原数据。浏览器私有资料位于.browser-profile，不应打包或提交。

## 验证与边界

执行 npm test：18项引擎测试通过。浏览器验证包含100/200/500万、物理数量增减、基线对比、独立HTML、密钥不导出、跨品牌清空旧覆盖和390px四页面无整体横向溢出。模型仅模拟响应测试，未真实消耗比赛额度；请在路演前配置专户并联调。更换行业/品牌需要对应门店及覆盖数据，当前完整预置案例仅星巴克，不能声称五行业都已调查完成。
