# 云策2027 · 户外媒介提案工作台

以星巴克上海六个官方门店地标为完整案例，连接覆盖分析、2027完整档期可售、区间刊例与交互提案。活动主题属于参赛策划假设，非品牌委托。

## 直接使用

解压整个交付包。离线查看与演示打开 `01_工作台.html`（仓库中为 `index.html`）；可调整100–500万元预算、增减车辆、查看来源、保存项目并导出交互HTML。

使用真实模型与实时库存：Windows双击 `start.cmd`，或桌面交付包里的 `启动完整版.cmd`。需要Node.js 18+及Edge/Chrome，首次运行联网安装Playwright。启动器同时打开本地工作台和独立比赛浏览器，请保持启动窗口打开。Python 3用于读取库存Excel，只用标准库。

开发方式：`npm install` 后 `npm start`；仅启动服务为 `npm run serve`，地址 `http://127.0.0.1:8766`。服务只监听本机，支持使用 `YUNCE_PORT` 改端口。

## 真实 Flash

从B1X“模型与算力→控制台→专用余额”复制比赛密钥，在工作台“模型连接设置”中填写，点击“使用Flash生成策略解读”。固定接口为B1X官方兼容地址，模型 `deepseek-v4.1-flash-1017`。密钥只在当前页面内存使用，刷新即清除，不进入项目文件、HTML导出或日志。

本版本已在2026-11-21使用比赛专户完成真实端到端调用，HTTP200并返回有效中文策略；调用前后28辆公交及198万元费用上界不变。版本实测记录与本页面是否已调用分别显示。无密钥、网络失败或额度不足时仍可使用规则摘要；模型不负责更改金额或库存。

## 同档期库存重查

在启动器打开的红豆标签页，用赛题提供的专户登录；不在源码中填写账号密码。回工作台选择2027完整档期，在“数据与证据”点击“同步同档期库存”。系统清除旧筛选条件，通过已登录页面查询、导出公交Excel，校验字段及档期后再替换数据。错误、登录失效或同步过程中改Brief时不应用过期结果。更换档期须重新同步，不可沿用原库存。

已实测2027-03-01至03-31及2027-04-01至04-30。同步范围为公交，复用已记录的六店覆盖；地铁资料保留自己的原始3月档期，未知可售、出口及面积不补零、不自动成案。浏览器私有资料保存在 `.browser-profile/`，不得提交或打包。

## 数据与价格

54条覆盖公交候选中，原3月导出精确匹配51条，43条有可售。列表总数552与实际导出431行口径不同，只使用实际导出范围。100万为14辆/5线路/65–100万元；200万为28辆/7线路/128–198万元；500万为71辆/14线路/321.5–499万元，均匹配6个锚点。

公交费用为每辆×（月刊例×计费月数＋本轮一次制作费），按已知费用上界约束预算。税费、折扣、计费月口径及其他费用须企业确认。库存是查询快照，非锁档承诺。500米平台轨迹关系不等于门店步行距离、独立触达或转化；未将2023人流外推为2027曝光。算法为覆盖优先贪心启发式，不保证全局最优。

## 1.2 版需求与执行

按2026-11-21学生版标准补充可编辑七要素Campaign假设书，另附一页HTML/PDF。客户展示名为脱敏模拟名称，公开品牌门店仅作为研究样本，不代表真实委托。新增生意目标、campaign单一主目标及对应衡量方法，未取得基线不编造2027曝光、到店和销售提升。

“需求与执行”中可修改上/下刊产能、两端天气缓冲、最低共同发布天数、素材前置期和执行预算预留。默认6辆/夜等参数均为团队假设，不是供应商确认数据。保守将上下刊作业都放入完整库存查询区间，共同发布窗口与库存租期分开，计费月数不自动打折。

默认200万元28辆：上下刊各5夜、两端共4夜缓冲，共同发布17天。500万元71辆只剩3天；启用产能约束后缩减到36辆以满足最低14天。模式会随预算和产能修改重算，保存项目可恢复；可切回仅媒体预算模式复现原三档结果。执行预留是内部预算额度，未知税费、施工及其他收费仍待业务报价。

客户HTML包含预算拆分、三档增量比较、资源集中度、监测验收计划、天气与替换处理、合同边界；其独立调整区随数量重算费用及发布窗口。误一补二按实际签署合同和归责处理，2026样本不是2027承诺。

27项自动化测试通过，另有新增交互回归；Flash与库存连接的真实联调记录沿用1.1版，新增执行参数不代表真实供应商产能已确认。
